OpenSAC: An Open Search-as-Code System for Deep Research Agents

✉ Corresponding author

Abstract

OpenSAC lets an external research agent express search as a Python program instead of a sequence of fixed tool calls. A generated program can batch queries, inspect documents, filter and fuse candidates, extract structured data, persist intermediate state, and print source-scoped results. OpenSAC executes the program in an isolated Docker sandbox and mediates every privileged operation through a capability broker. The system implements the public Search as Code abstraction as an open, inspectable runtime for controlled research; it does not attempt to reconstruct any proprietary search engine.

Method overview

Search orchestration moves from the model context into code.

Motivation

Why express search as code?

Tool-calling agents must repeatedly expose intermediate retrieval actions and results to the control model. This consumes context and makes multi-step operations such as query batching, filtering, joins, and evidence fusion cumbersome.

Generated code provides ordinary control flow and a local workspace. Large intermediate results can stay off-context while the bounded handoff remains explicit and attributable to readable source URLs.

  1. 01

    Programmable retrieval

    Batch, filter, join, rank, and select evidence using ordinary Python control flow.

  2. 02

    Inspectability and isolation

    Keep generated code readable while denying direct access to networks and credentials.

  3. 03

    Research instrumentation

    Expose budgets, partial failures, traces, phase timings, and worker lifecycle controls.

System

A small capability surface for complete research passes.

Namespace Operations Purpose
sdk.search search · many · fuse_rrf

Retrieve and fuse candidates while preserving provenance.

sdk.content fetch · read · grep · passages

Fetch, locate, and inspect evidence with explicit cursors.

sdk.llm extract · extract_many · complete

Optional schema-checked extraction and model calls.

sdk.workspace JSON · JSONL · artifacts

Persist structured artifacts across executions in one session.

sdk.capabilities() top-level call

Inspect active contracts, mechanisms, and deployment limits.

Example

A Search-as-Code program in twelve lines.

research.py 
from opensac_sdk import sdk

queries = [
    "Search as Code agents",
    "programmatic retrieval",
]

results = sdk.search.many(queries)
evidence = sdk.search.fuse_rrf(results)

selected = [hit for hit in evidence if hit.score > 0.1]
sdk.workspace.write_json("evidence.json", selected)
for hit in selected[:8]:
    print(f"EVIDENCE source={hit.source!r} title={hit.title!r}")

Research scope

When the model, retrieval backend, and evaluation protocol are held constant, does composing search primitives in generated code improve quality, context efficiency, or the latency–cost trade-off over model-visible tool calls?

OpenSAC deliberately provides the execution runtime—not the agent loop, evaluation protocol, or a hosted search product.
